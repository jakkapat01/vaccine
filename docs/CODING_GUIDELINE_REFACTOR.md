# Coding guideline refactor — vaccine

วันที่ตรวจ 9 ตุลาคม 2569

ปรับเฉพาะรูปแบบและโครงสร้างโค้ดตาม Guideline_Checksheet.pdf โดยคงพฤติกรรมเดิม ได้แก่ State และเลข enum, ปุ่ม D2–D5, PIN/สิทธิ์, โหมด Transport/Use/Return/Replace/Settings, การแสดงผล OLED, คำสั่งและคำตอบ Serial, การคำนวณ Health/Risk, Alarm, Sensor Fault และค่าตั้งเวลาของฮาร์ดแวร์

## ขอบเขต

แก้โค้ดแอปพลิเคชันใน Src และ Inc จำนวน 40 ไฟล์ รวมไฟล์ใหม่ app_constants.h และเพิ่ม .clang-format เพื่อรักษารูปแบบ

คงไฟล์ของผู้ผลิตและไฟล์แพลตฟอร์มเดิม: Src/HAL, Inc/HAL, CMSIS ภายนอกโปรเจกต์, startup, system_stm32f4xx.c, syscalls.c, sysmem.c และ stm32f4xx_hal_conf.h จึงไม่อ้างว่าไลบรารีทั้งโครงการผ่านกฎของเอกสารนี้ การแก้ทั้งหมดมุ่งที่โค้ดแอปพลิเคชันที่เขียนเอง

## รายการปรับตามเกณฑ์

| กฎ | การดำเนินการ |
|---|---|
| 1 | ใช้คอมเมนต์แบบ /* ... */ ในโค้ดแอปพลิเคชัน |
| 2 | แยกวงเล็บปีกกาของบล็อกควบคุมและฟังก์ชันเป็นคนละบรรทัด |
| 3 | จัดช่องว่างรอบตัวดำเนินการ |
| 4 | แยกคำสั่งกำหนดค่าและประกาศตัวแปร แยก chained assignment โดยรักษาลำดับการเขียนค่าเดิม |
| 5 | ตั้งชื่อค่าคงที่ เช่น จำนวนหลอด ความยาว PIN เวลาเปิด ช่วงเซนเซอร์ ขนาด buffer และพิกัดจอ |
| 6 | เปลี่ยน ternary เป็น if/else หรือฟังก์ชันเลือกข้อความที่มีพารามิเตอร์ Boolean |
| 7 | ตรวจทางเดินโค้ดโดยคง fallback และค่า State เดิม ไม่เปลี่ยน flow เพื่อแก้ style |
| 8 | ลบ macro ตั้งค่ารุ่นเก่าที่ไม่ได้ใช้ ตรวจ unused definitions ด้วย compiler |
| 9 | ไม่ใช้ integer literal แบบ octal |
| 10 | เติม U ให้ค่าคงที่ที่ใช้เป็น unsigned และกำหนดชนิดค่าคงที่สำคัญให้ชัดเจน |
| 11 | ใช้ prototype แบบระบุชื่อพารามิเตอร์ และ void สำหรับฟังก์ชันที่ไม่มีพารามิเตอร์ |
| 12 | ตรวจการกำหนดค่าก่อนอ่านและตรวจคำเตือน uninitialized |
| 13 | เปรียบเทียบ flag/bitmask กับศูนย์อย่างชัดเจน และเพิ่ม explicit cast ในจุดแปลงชนิด |
| 14 | ใส่วงเล็บให้ลำดับการคำนวณชัดเจน โดยรักษา expression tree เดิม |
| 15 | ยกเลิก float != ในการตรวจ OPEN_SECONDS และใช้การเปรียบเทียบมากกว่าค่าที่ตัดเศษ หลังตรวจช่วงบวกและ finite แล้ว จึงยังปฏิเสธเศษทศนิยมเหมือนเดิม |
| 16 | ใช้ตัวนับ loop แบบจำนวนเต็ม |
| 17 | ใช้เงื่อนไขเปรียบเทียบหรือ Boolean ใน if/while/for |
| 18 | ใส่ compound statement ให้ทุกแขนงและ loop |
| 19 | เติม else ที่ไม่ทำอะไรในแขนงที่ต้องคงพฤติกรรมเดิม |
| 20 | ตรวจ unconditional break ท้าย switch clause โดยคง grouped case ที่ใช้ร่วมกัน |
| 21 | เพิ่ม default แบบไม่ทำอะไรเมื่อเดิมไม่มี |
| 22 | วาง default เป็นแขนงสุดท้าย |

ค่าที่เป็นข้อมูลโดยตรง เช่น bitmap ของฟอนต์และชุดคำสั่งเริ่มต้น OLED ยังคงอยู่ในตารางข้อมูลเดิม ส่วน 0/1 ที่หมายถึงศูนย์ ค่า flag และ index ตามลำดับคงไว้เมื่อความหมายชัดเจน กฎ 5 ระบุให้หลีกเลี่ยง magic constants ไม่ได้กำหนดให้เปลี่ยนทุกไบต์ของตารางเป็น macro

ST_BOOT และชื่อ State ทุกตัวคงไว้เพื่อรักษา interface, ค่าที่รายงานผ่าน Serial, sentinel สำหรับการตรวจเปลี่ยนหน้า และการตอบสนองของฟังก์ชันเมื่อได้รับ State นั้น ไม่มีการเปลี่ยนหน้าเริ่มต้นจาก HOME

## ผลตรวจ

- Build โปรเจกต์จริงใน Debug ด้วย arm-none-eabi-gcc และ make -B -j16 all ผ่าน: 0 errors, 0 warnings
- ตรวจเพิ่มด้วย -Wall -Wextra -Wconversion -Wfloat-equal -Wuninitialized ที่ -O2: ไม่พบ diagnostics ในโค้ดแอปพลิเคชัน
- ทดสอบ ARM emulator สำหรับ Sensor Fault, ช่วงเซนเซอร์, Nurse flow, เปิดอัตโนมัติ, ADC Watchdog, TIM2 และ LED: 109 assertions ผ่าน
- ทดสอบเทียบฉบับก่อนและหลังแก้ 14,152 snapshots: fingerprint ของข้อมูล App, Event Log, คำตอบ Console และลำดับคำสั่งวาด OLED ตรงกันทั้งหมด รวมกรณี state ไม่รู้จัก
- ตรวจไฟล์ที่นำเข้าโปรเจกต์จริงเทียบกับ candidate ที่ทดสอบแล้ว: ตรงกัน
- ไฟล์ HAL/แพลตฟอร์มที่ระบุในขอบเขตไม่เปลี่ยน

ชุดทดสอบรุ่นเก่าอีก 6 ชุดอ้าง flow หรือสถานะหลอดที่เลิกใช้แล้ว ผลไม่ผ่านหรือ compile ไม่ได้เหมือนกันทั้งก่อนและหลังแก้ จึงไม่ใช้เป็นหลักฐานผ่านของเวอร์ชันนี้ และไม่ได้แก้พฤติกรรมปัจจุบันให้ย้อนกลับไปตรงกับชุดทดสอบเก่า

การตรวจนี้เป็นการตรวจตาม checksheet และ regression test ไม่ใช่ใบรับรอง MISRA เต็มมาตรฐาน ยังไม่ได้แฟลชและทดลองกับบอร์ดจริงหลัง refactor และไม่ได้รับรองเวลา execution ระดับ instruction ว่าเท่ากันทุก cycle
