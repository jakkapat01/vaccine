# Interrupt ปุ่ม D2–D5

| ปุ่ม | GPIO | ISR |
|---|---|---|
| D2 | PA10 | EXTI15_10_IRQHandler |
| D3 | PB3 | EXTI3_IRQHandler |
| D4 | PB5 | EXTI9_5_IRQHandler |
| D5 | PB4 | EXTI4_IRQHandler |

ทั้งหมดใช้ EXTI ขาขึ้นและขาลง Priority 5 โดย HAL_GPIO_EXTI_Callback เรียก Buttons_Edge

เมื่อปุ่มเปลี่ยนระดับ CPU เข้า ISR ได้ระหว่าง main loop รวมถึงระหว่างส่งภาพ OLED แบบ blocking ตราบใดที่ไม่ได้ปิด interrupt หรือกำลังอยู่ใน ISR ที่มี priority สูงกว่า/เท่ากัน ISR บันทึกเวลา นับเหตุการณ์ และใส่คำสั่งลงคิว ไม่ส่ง OLED, ไม่ใช้ HAL_Delay และไม่สั่งเปิดสลักใน ISR

main loop ใช้ Buttons_GetEvent ดึงจากคิว ไม่ได้อ่าน GPIO วนเพื่อตรวจปุ่มแบบเดิม เมนูยังต้องรอ main loop ประมวลผลหลังงานปัจจุบันเสร็จ แม้การรับ interrupt จะเกิดก่อนหน้านั้นแล้ว

การกดหนึ่งครั้งต้องกดค้างอย่างน้อย 40 ms แล้วปล่อย จึงเกิดคำสั่งหนึ่งรายการ กดค้างไม่ทำซ้ำ ปุ่มที่กดค้างตอนบูตต้องปล่อยก่อน และปุ่มที่กดซ้อนกันจะไม่สั่งงาน คิวเก็บได้ 15 รายการ หากเต็มจะนับ DROPPED และไม่เขียนทับคำสั่งเก่า

## ลองผ่านเว็บ Serial Terminal

ส่งคำสั่ง `IRQ` ก่อนและหลังกดปุ่ม เช่น:

```text
IRQ EDGES D2=2 D3=0 D4=6 D5=4 DROPPED=0
```

ตัวนับเป็นจำนวนขอบสัญญาณจริง รวมการเด้งของสวิตช์ จึงไม่ใช่จำนวนครั้งที่กด และอาจมากกว่า 2 ต่อหนึ่งครั้ง ตัวนับยังเพิ่มแม้หน้าแอปไม่รับปุ่มนั้น เช่น D4 ในหน้า BOOT แต่จะไม่ข้ามขั้นตรวจสิทธิ์

ดูหลักฐานด้วย debugger ได้โดยตั้ง breakpoint ใน EXTI3_IRQHandler / EXTI4_IRQHandler / EXTI9_5_IRQHandler / EXTI15_10_IRQHandler หรือ Buttons_Edge แล้วกดปุ่ม อย่าหยุด debugger ค้างขณะกำลังทดสอบกลไกที่ต้องจับเวลา

UART RX และ SysTick ยังใช้ interrupt เหมือนเดิม PWM Servo ใช้ TIM3 ฮาร์ดแวร์ตามเดิม

ตรวจ Compile/Link และ CubeIDE headless Build แล้ว ไม่ได้ flash หรือทดสอบสัญญาณจริงบนบอร์ด

หลังติดตั้งให้ F5 -> Clean/Build -> ลงบอร์ดใหม่ จากนั้นกดแล้วปล่อย D2–D5 เพื่อใช้งาน
